# 每月維修與整新故障報表：接手者只需上傳 Excel

分析網站：https://campcool.github.io/TITAN-STAR/

## 每次更新只做三件事

1. 在這個 `date` 資料夾按 **Add file → Upload files**，上傳當月兩份 Excel。
2. 按 **Commit changes** 完成上傳。檔名使用 `115年 08 月維修報表.xlsx` 與 `115年8月整新故障.xlsx`。
3. 開啟分析網站。網站每次開啟都會檢查，並顯示最新月份與更新結果；已開著的頁面按「檢查更新」即可。

不需要改程式、不需要輸入指令、不必等每月 1 號，也不需要重新部署網站。
GitHub 的檔案快取偶爾需要稍等；若顯示「正在更新或快取尚未同步」，稍後按「檢查更新」。

## 新月份與更正

- 保留所有歷史月份 Excel。不要刪除舊月份，也不要只留下最新一份。
- 修改同月份資料：直接用同檔名覆蓋；網站依檔案內容版本判斷是否更新，不看檔案筆數是否增加。
- 也可以上傳 `115年 08 月維修報表-更正版.xlsx`。更正版優先於原版，整個月份取代，不重複累加。
- 再次更正：覆蓋同一更正版，或使用 `-更正版2.xlsx`、`-更正版3.xlsx`，數字越大越優先。
- 同月份同優先序只能有一份。不要同時放「08 月」和「8 月」兩份原版。
- 民國年與西元年都可使用，例如 `2026年 08 月維修報表.xlsx`。
- 整新故障表可使用 `115年8月整新故障.xlsx`；同樣支援 `-更正版.xlsx`、`-更正版2.xlsx`。
- Excel 暫存檔 `~$...xlsx` 會忽略；其他說明文件不參與分析。

## Excel 要保留的格式

維修報表沿用目前格式：`故障零件總數` 彙總分頁、各型號／分類的維修明細分頁。
保留日期、型號、故障原因、故障內容與零件欄位原來的名稱。新型號與新月份會自動納入，未知分類顯示「其他」。
日期須為有效日期；零件數量不可為負數。多數維修日期應符合檔名月份，少量跨月資料會提示並保留報表歸屬。
整新故障表沿用「機種為欄、整新測試數／測試正常數／整新故障數／原因為列」的格式。請勿把年度統計、品號主檔或其他格式改名放進這裡。單檔上限 25 MB。

## 如何確認成功

網站會顯示「已更新 N 份 Excel」，分析期間預設最新的維修報表月份。
用「切換月份與歷史範圍」查看近 3／6／12 個月或全部歷史。前月缺資料時不計月增減。
GitHub Actions 的 **檢查維修 Excel** 也會列出各月解析筆數及需要修正的內容。

## 遇到問題

| 提示 | 如何處理 |
|---|---|
| 檔名無法辨識／同月兩份 | 依上方命名範例修改，保留唯一有效版本 |
| 找不到日期表頭 | 把 Excel 欄位名稱與位置恢復成現有月報格式 |
| 日期不正確／月份不符 | 依提示的工作表與列號修正，不要只把舊報表改名 |
| 來源 Excel 被移除 | 放回原檔；歷史月份應持續保留 |
| GitHub 限制查詢／網路失敗 | 不要連續重新整理，稍後按「檢查更新」 |
| 瀏覽器空間不足 | 本次仍可使用最新資料；關閉重開後會重新讀取 Excel |

整批更新通過驗證後才套用；其中一份失敗就保留該裝置上一版有效資料。首次使用或清除瀏覽器資料後，失敗時可能只看到網站隨附的歷史快照，頁面會明示更新未完成。

這條流程處理標準維修月報與整新故障矩陣。若日後改成完全不同的 Excel 結構或新增業務計算定義，仍需修改解析規則；正常的月份新增、內容更正、新型號無須改程式。
